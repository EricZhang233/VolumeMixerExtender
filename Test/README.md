# 项目测试

在仓库根目录执行：

```powershell
dotnet test
```

这是唯一对外测试入口，不需要参数、分区或其他命令。根目录测试工程自动准备 CMake 测试配置、编译 Debug 测试产物，然后完整执行所有 CTest 和发布工作流契约。

需要 Windows、Visual Studio 2026 C++ 工具链、Windows SDK、CMake、PowerShell 7、Node.js 和 .NET 10 SDK。测试会打开管理器冒烟检查窗口，需要可交互桌面。

测试覆盖 Core、外部宿主、诊断组件、驱动包、WPF 管理器和静默更新。更新测试使用隔离临时安装目录，验证只接受正式版、12 小时检查间隔、SHA256、包路径及完整性校验、事务替换、失败回滚、配置保留和并发互斥，不停止真实后台程序或访问网络。任一阶段失败或超时，dotnet test 返回非零退出码；成功不会自动提交、推送或发布。普通 build/run 和远端发布不运行测试套件。

手动更新覆盖检查结果与下载目标的一致性、检查失败或无更新时清除旧目标、对应 Release 页面地址、管理器按钮切换及同排布局、更新发起进程身份校验，以及旧命令行程序的事务清理与回滚。录制保护直接启动后台宿主，发布契约禁止重新引入 CLI 入口或包成员。浏览器实际打开、窗口前台恢复和完整安装重启仍需交互验收。

`core.logging` 与更新器日志压力夹具分别覆盖 8 个并发生产者、12000 条警告、容量为 1 的队列溢出、关键日志完整性、低优先级丢弃计数、6 MB 单条记录触发分卷、30 天与总容量清理、无 BOM UTF-8、UTC、调用位置、敏感信息脱敏、操作关联与耗时，以及退出时尾部错误刷盘。夹具使用隔离临时目录，不读取或清理实际日志。

## 结果

`core.presentation` 同时验证录制状态的跨进程预热缓存、宿主退出后的失效，以及旧应用行、正在执行的音频回调和列表重建之间的句柄所有权。测试不打开或接管系统声音面板；底栏三栏/四栏、强调底色和实机反复开关仍需交互验收。

报告位于 `Test/artifacts/<时间与编号>/`：

- `summary.md` 与 `summary.json`：阶段状态及日志入口。
- `00.log` 等：命令与完整输出。
- `test-results.xml`：全部 CTest 的 JUnit 结果。

测试构建缓存位于 `obj/local-tests`，不改变普通构建目录的测试开关，也不打包 Release。内部 PowerShell、CTest 和 Node.js 脚本由 dotnet test 自动调用，无需分别执行。

真实音频设备、不同缩放、应用重启后的系统行为和实际 GitHub 发布仍需后续实机验收。远端保留依赖签名、哈希、架构和包完整性校验，测试不作为远端构建门槛。
